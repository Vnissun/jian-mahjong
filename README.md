# 集安麻将--吉林通化集安麻将玩法，撅夹钓

使用 **Cocos Creator 3.8.8**。外层 `assets` 是历史代码，`_disabled` 中的测试和联机模块不参与游戏构建；请修改本目录 `assets/scripts`。

## 好友线上对战

执行 `npm run build:server`、`npm start`，打开 `http://127.0.0.1:7458`。大厅可好友开房、复制邀请链接或输入六位房间号加入。房主在开局前可增删机器人；真人全部准备后房主开局，空位自动补齐机器人。每位玩家仅能看到自己的暗手，支持刷新及断线重连。详见 [BOTS-UPDATE.md](BOTS-UPDATE.md)；公网部署见 [DEPLOY.md](DEPLOY.md)。

## 运行

1. 在 Cocos Dashboard 中添加本目录，使用 Creator 3.8.8 打开，等待资源导入完成。
2. 打开 `assets/game.scene`，点击编辑器预览。
3. 大厅选择底分、满贯、封圈、七小对和报听对踢，点击“开始游戏”。默认底分 1、满贯 32、封圈 3、七小对和吃牌开启。当前为一人对三名 AI。

本次已生成 `build/web-repaired`。在本目录执行 `npm run preview` 或 `node tools/serve.cjs`，打开 <http://127.0.0.1:7457>。服务仅监听本机。停止服务按 Ctrl+C。

重新构建可在编辑器选择 Web Desktop，或执行 PowerShell：

```powershell
& 'C:\ProgramData\cocos\editors\Creator\3.8.8\CocosCreator.exe' --project $PWD.Path --build 'configPath=buildConfig.web.json'
```

编辑器安装位置不同时调整命令。构建配置指定游戏场景、横向网页模板和输出目录。Cocos 的命令行构建成功退出码为 36。

## 操作

- 点手牌一次选中，第二次点击同一张或点击“出牌”确认。
- 报听：仅单吊、夹、撅、对倒可报；普通两面听不可报听，可继续换牌。点击“报听”，仅亮起合法弃牌，点选后再次点击确认。若有多个听口，再选择声明方案；如 1234 单吊 1 或 4，必须选一个，另一个不能胡。声明时锁定听口及手牌，以后只能打出新摸到的牌，不可换听，仍可胡牌；允许不影响原听口的暗杠、已开门点杠、加杠及已有字杠补毛。
- 杠：点“杠”，从组合菜单选择普通暗杠、特殊杠、加杠或补毛。“过”可取消。
- 他家出牌时，先处理胡牌机会，再处理碰杠。选择“过”放弃本次机会。
- 吃牌只吃上家的数牌；胡、碰、杠机会全部处理后，点击“吃”选择三张顺子的组合，吃后出一张牌。
- 报听者旁边向所有人显示单吊、对倒、夹胡或撅等具体听法。
- 点击任意自己的手牌可查看余量；报听后持续显示听牌余量。估计为 4－公开已见－自己持有，包含他家暗手及牌墙，不透露暗牌。
- 流局或胡牌后查看结算，手动进入下一局；大厅按钮可重新开桌。

## 麻将规则

本项目采用以下集安麻将玩法。不同地区或牌桌的叫法可能不同，以本节约定为准。

### 1. 牌张与开局

- 四人对局，使用万、筒（饼）、条及东南西北、中发白，共 34 种、136 张牌，不含花牌。
- 庄家起手 14 张，闲家起手各 13 张，庄家先出牌。牌墙尾部保留 14 张作为杠后补牌区。
- 正常对局随机洗牌、发牌和摸牌，不按听牌情况安排需要的牌。
- 房间可选择底分 1／2／5，满贯 32／64／128／256／无限，封圈 1／2／3／4／8，可选择是否开启七小对、报听对踢。固定允许吃牌。

### 2. 吃、碰、杠与站立

- **吃**：只能吃上家打出的数牌，组成同花色连续三张；字牌不能吃。
- **碰**：持有两张相同牌，可以碰他家打出的第三张。
- **明杠**：持有三张相同牌，杠他家打出的第四张。
- **暗杠**：自己持有四张相同牌。普通暗杠对其他玩家隐藏，自己可看到一张用于辨认；局末结算后公开。
- **加杠（补杠）**：已有一组碰牌，再摸到第四张相同牌，可以补成杠。
- 胡牌响应优先于碰、杠，碰、杠优先于吃。每局一人胡牌后结束，不继续血战。
- **站立**指尚未开门。吃牌、碰牌算开门；数牌明杠、加杠算开门。暗杠、字牌杠及特殊字杠不使玩家开门；已经开门后不会因开杠恢复站立。

### 3. 特殊字杠与补毛

- **四风杠**：东、南、西、北各一张组成特殊杠。
- **三元杠**：中、发、白各一张，再加任意一张中、发或白组成特殊杠。
- 特殊字杠需要亮出，但按暗杠计分，不算开门。
- **补毛**：已有四风杠后，可以继续补风牌；已有三元杠后，可以继续补中、发、白。不能补其他牌类。
- 完成杠或补毛后，从尾部补牌区摸一张。符合条件时，可在补摸之前先报听，随后补摸的牌可以胡。
- 普通加杠可以被抢杠胡；普通明杠、暗杠及首次组成的特殊字杠不设抢杠响应。
- 四风／三元**补毛的那一张**先询问胡牌，再询问碰牌，不能吃，也不能转为明杠。报听玩家不能碰。
- 补毛牌被碰或被胡时，只转移本次补出的牌，原字杠保留；不计本次补毛分，也不再补摸。无人响应或全部选择过，才完成补毛并补摸。

### 4. 胡牌条件

普通胡牌须由四组合法面子和一对将组成，吃、碰、杠均计入面子；顺子须为同花色连续三张，刻子须为三张相同牌。同时满足：

1. **有幺九**：至少包含一张一、九或字牌；风牌和中发白都算幺九。
2. **有刻子**：至少一组刻子或杠；一对相同的中、发或白可豁免此要求，但不改变四组面子加一对将的结构要求。
3. **不缺门**：万、筒、条齐全；纯清一色、混清一色可豁免缺门。

自摸、点炮、抢杠均须满足合法牌型及相应门槛。普通胡牌无需强制先报听；七小对有单独的报听要求。

### 5. 报听与自动出牌

| 听法 | 含义 | 报听倍数 |
| --- | --- | --- |
| 单吊 | 等一张牌配成将 | ×2 |
| 对倒 | 两对中等一对补成刻子，另一对作将 | ×2 |
| 夹胡 | 如一三等二，补顺子中张 | ×2 |
| 撅 | 一二等三，或八九等七的边张听法 | ×4 |

- 普通两面听不能报听，但可继续换牌、按普通胡牌条件胡牌。
- 同一手牌可能有多种拆解、听法或可选听牌，报听时按界面选择声明方案；之后锁定该方案和对应听牌，不可换听或扩大听口。
- 报听后不能吃、碰，不能随意更换原手牌；未胡的新摸牌自动打出。
- 他家打出可胡的牌时，仍可选择“胡”或“过”。
- 报听后自摸到可胡的牌，展示新牌 **5 秒后自动胡牌**。期间合法按钮仍可用，可提前胡牌；主动出牌或进行合法杠牌操作会取消原自动胡计时。新的补摸若再次自摸，则重新展示 5 秒。
- 报听后仍可进行不改变原听法、听口及合法手牌结构的杠：站立报听不能明杠他家的牌；已经开门报听可以符合条件地明杠。暗杠不能拆走原顺子或将牌所需的牌。已有碰牌的加杠、已有特殊字杠的补毛只能使用新摸到的牌。

### 6. 胡牌积分

**胡牌后，另外三家都要分别付款。每一家与胡家单独计算，不能把三家倍数合在一起乘。**

```text
每家胡牌付款 = 底分 × min(该家适用倍数的乘积, 满贯上限)
选择“无限”时不封顶。
本局积分变化 = 胡牌积分变化 + 本局杠分、补毛分净额
```

| 项目 | 倍数或计算方式 |
| --- | --- |
| 庄家 | 胡家或该付款方为庄家，该笔 ×2，只乘一次 |
| 普通报听 | ×2，包含单吊、对倒、夹胡 |
| 报撅 | ×4 |
| 普通站立 | 胡家站立 ×2；该付款方站立再 ×2；三家清、四家清另见下文 |
| 自摸 | 三家各自 ×2 |
| 点炮／抢杠责任 | 仅点炮者／被抢杠者该笔 ×2，其他两家仍正常付款 |
| 杠后自摸 | 紧接杠后补摸胡牌，在自摸 ×2 的基础上再 ×2 |
| 杠后点炮 | 紧接杠后打牌点炮，仅责任方在点炮 ×2 的基础上再 ×2 |
| 混清一色 | 数牌只有一种花色，且带字牌，×2 |
| 纯清一色 | 只有一种花色的数牌、不带字牌，×4，不再叠加混清 |
| 飘胡／对对胡 | 四组刻子或杠加一对将，不能有顺子或吃牌，胡牌分额外 ×2 |

杠后加成只适用于紧接该次杠、补毛的对应行为，本局早先有人杠过，不会给之后的普通胡牌持续加倍。

#### 报听对踢

- **关闭（默认）**：胡家与该付款方的报听倍数取较高值。普通对撅为 ×4，撅对撅仍为 ×4。
- **开启**：双方报听倍数相乘。普通对普通为 ×4，普通对撅为 ×8，撅对撅为 ×16。
- 第三人的报听不影响这笔双方结算；未报听按 ×1。

#### 三家清、四家清

| 情况 | 固定基础 | 是否另算站立 |
| --- | --- | --- |
| 三家清：胡家已开门，另外三家均站立 | ×4 | 不再叠加胡家或付款方站立 |
| 四家清：四人均站立 | ×16 | 不再叠加胡家或付款方站立 |

两者固定基础已经包含站立因素，不能重复加倍；庄家、报听、自摸、点炮、清一色等其他适用倍数继续相乘。七小对不叠加三家清、四家清。

**示例**：底分 1、无限满贯、胡家是闲家且自摸，无报听或其他胡型加成：三家清时庄家付 16、另两家各付 8；四家清时庄家付 64、另两家各付 32。

### 7. 七小对与豪华七对

- 需房间开启七小对；手中 14 张牌组成七对，不得有吃、碰、杠副露。
- 四张相同牌保留在手中时，可视为两对，不必开杠。
- 仍须有幺九、不缺门；纯清、混清可豁免缺门。七小对豁免刻子要求。
- 胡牌前必须先报听单吊。
- 固定基础 **×8**，胡家站立 **×2**、普通单吊报听 **×2**，形成基础 **×32**。庄家、自摸、点炮、清一色、付款方站立及报听对踢等适用倍数继续计算；不额外乘三家清、四家清或飘胡。

| 手牌中的四同组数 | 名称 | 七小对额外倍数 |
| --- | --- | --- |
| 0 组 | 七小对 | ×1 |
| 1 组 | 豪华七对 | ×2 |
| 2 组 | 双豪七对 | ×4 |
| 3 组 | 三豪七对 | ×8 |

四同组必须留在暗手里，每多一组额外翻倍；三组四同共十二张，再加一对将即可构成三豪七对。上述胡牌分同样参与满贯封顶。

### 8. 杠分与补毛分

**杠分不看谁供牌，均由另外三家各付一份。局中只记录，胡牌或荒庄时统一结算，不提前公开杠分；杠分不参与胡牌满贯封顶。**

下表为底分 1、未计庄家倍数时，其他每一家应付的单份分数：

| 杠牌种类 | 明杠／加杠 | 暗杠 |
| --- | --- | --- |
| 二筒（饼）、八万的四张同牌 | 4 | 8 |
| 一筒（饼）、幺鸡（一条）、中／发／白任意一种的四张同牌 | 2 | 4 |
| 其他四张同牌，包括四张相同风牌 | 1 | 2 |
| 四风／三元特殊组合杠 | — | 4（基础 2，再按暗杠 ×2） |
| 每次成功补毛 | 1 | 不再额外乘暗杠倍数 |

- 开杠者或该付款方为庄家，该笔再 ×2，只乘一次；上述分数再乘房间底分。
- 加杠按最终成立的杠记录，不对原碰牌重复收杠分；补毛则每次成功各计一笔。
- 普通暗杠牌种只允许本人查看，其他人局末才可看到。
- 荒庄也结算本局已完成的杠和补毛；失败、被抢胡或被碰走而未完成的那次操作不收相应杠／补毛分。

**示例**：底分 1，庄家九筒明杠，闲家 A 北风明杠，另两家 B、C 无杠，最终杠分净额为庄家 **+4**、A **+2**、B **−3**、C **−3**。

### 9. 荒庄、轮庄与对局操作

- 庄家胡牌或荒庄，庄家连庄；闲家胡牌，庄位按东→南→西→北推进，四个庄位完成一封圈。达到房间设定封圈数后结束整桌。
- 每次需要玩家行动时有 **15 秒**倒计时；成功杠牌、补摸或进入新响应阶段后重新计时。出牌超时由系统自动出牌，响应超时按过处理。
- 离线玩家由机器人托管，使用同一玩家身份重连后可接管原座位；手动返回对局后继续操作。
- 胡牌或荒庄后显示四家结算，可以“查看牌桌”查看所有剩余手牌。结算展示胡家手牌、副露及单列的胡牌张。
- 好友房不足四人时，可由房主添加机器人补齐；录音、快捷语音和投掷表情仅用于互动，不影响牌型和积分。

报听后杠牌：每次操作都检查原声明听型和选定听牌；暗杠不得拆走原顺子或将牌中的牌。站立报听不能点杠，已开门者可以三张杠他家一张。已有风/元特殊杠可补同类新摸毛，杠后尾部补牌、可自摸或打牌点炮。宝塔 Node.js 逐步部署说明见 [BAOTA-NODEJS.md](BAOTA-NODEJS.md)。

运行环境已验证 Node.js 16.20.2。宝塔选择此版本，生产入口为 `server/start-production.cjs`；服务端及健康检查不依赖全局 fetch。

手机显示已改为横屏整页适配，电脑保留原方向。已部署站点可仅更新网页包，步骤见 MOBILE-UPDATE.md；全屏按钮需点击触发，iPhone 受浏览器支持限制。

最新版本支持杠后补摸前报听与服务端访问密码，部署必须使用整站反向代理，详见 ACCESS-UPDATE.md。联机洗牌由加密随机数驱动，不存在听牌偏向摸牌。

音效：34种牌中文报牌、吃碰杠补毛报听胡牌等动作语音；按钮/摸牌/出牌/胜负提示由浏览器音频合成。页面左上角可静音和调节音量，设置保存在本浏览器。手机需先点击页面解锁音频。新增语音源在 web-assets/sounds，构建后执行 node tools/sync-web-audio.cjs 同步资源；打包脚本自动同步。
